## 🔀 3. Логика Подключения и Загрузки Курса Валют (USD / BYN)

Все расчёты в системе ведутся в **USD** с автоматическим пересчётом в **BYN** (Белорусский рубль).

### Алгоритм получения актуального курса Нацбанка РБ:
1. **Основной источник (Парсинг официального сайта НБ РБ)**:
   - Запрос на страницу: `https://www.nbrb.by/statistics/rates/ratesdaily`
   - Регулярным выражением `(\d{1,2}[.,]\d{2,4})` в блоке `"Доллар США"` / `"USD"` извлекается значение курса (например, `3.2545`).
2. **Резервный источник (Официальный REST API НБ РБ)**:
   - Эндпоинт 1: `https://api.nbrb.by/exrates/rates/431`
   - Эндпоинт 2: `https://www.nbrb.by/api/exrates/rates/USD?parammode=2`
   - Формула курса: `Курс = Cur_OfficialRate / Cur_Scale`
3. **Международный резервный шлюз (Fallback)**:
   - В случае сетевых блокировок или недоступности серверов НБ РБ используются REST APIs:
     - `https://open.er-api.com/v6/latest/USD`
     - `https://cdn.jsdelivr.net/npm/@fawazahmed0/currency-api@latest/v1/currencies/usd.json`

## 🗿 4. Полная Логика Конструктора Памятников (Monument Builder)

Конструктор предназначен для точного расчёта объёма (м³), массы (кг) и стоимости гранитного комплекта на основе габаритов и выборок.

### 4.1. Справочник Гранита (Материалы)
Каждый тип камня имеет плотность ($\text{кг/м}^3$) и базовую цену за м³ ($/м³):
- **Габбро-Диабаз (Карелия)**: Плотность = 3000 кг/м³, Базовая цена = 1100 $/м³ (прямая гравировка портрета: ДА).
- **Лезниковский (Красный)**: Плотность = 2700 кг/м³, Базовая цена = 1600 $/м³ (портрет на медальоне/стекле).
- **Аврора (Финляндия)**: Плотность = 2750 кг/м³, Базовая цена = 1750 $/м³.
- **Дымовский (Балтийский)**: Плотность = 2800 кг/м³, Базовая цена = 1350 $/м³.
- **Малиновый Кварцит**: Плотность = 2650 кг/м³, Базовая цена = 2100 $/м³.
- **Мансуровский (Белый)**: Плотность = 2600 кг/м³, Базовая цена = 1250 $/м³.

---

### 4.2. Расчёт Стелы (Плиты)
* **Параметры**: Высота ($H$), Ширина ($W$), Толщина ($T$) в сантиметрах.
* **Объём стелы (м³)**:
  $$\text{V}_{\text{стелы}} = \frac{H \times W \times T}{1\,000\,000}$$
* **Масса стелы (кг)**:
  $$\text{M}_{\text{стелы}} = \text{V}_{\text{стелы}} \times \text{Плотность}$$
* **Коэффициент формы (Резка)**:
  - Прямоугольная (классика): $\times 1.0$
  - Волна / Срез: $\times 1.15$
  - Плечики / Овал: $\times 1.25$
  - Сложная фигурная (Арка, Сердце): $\times 1.35$
  - Резной Крест / Изображение: $\times 1.50$
* **Итоговая цена стелы ($)**:
  $$\text{Cost}_{\text{стелы}} = \text{V}_{\text{стелы}} \times \text{Цена\_за\_м3} \times \text{Коэффициент\_формы}$$

---

### 4.3. Расчёт Тумбы (Подставки)
* **Параметры**: Длина ($L$), Ширина ($W$), Высота ($H$) в сантиметрах.
* **Объём тумбы (м³)**:
  $$\text{V}_{\text{тумбы}} = \frac{L \times W \times H}{1\,000\,000}$$
* **Масса тумбы (кг)**:
  $$\text{M}_{\text{тумбы}} = \text{V}_{\text{тумбы}} \times \text{Плотность}$$
* **Цена тумбы ($)**:
  $$\text{Cost}_{\text{тумбы}} = \text{V}_{\text{тумбы}} \times \text{Цена\_за\_м3}$$

---

### 4.4. Расчёт Цветника (Открытый / Закрытая плита)
Пользователь выбирает тип цветника и задаёт размеры:
- Длина ($L_{\text{цв}}$) в см
- Ширина ($W_{\text{цв}}$) в см
- Толщина ($T_{\text{цв}}$) в см
- Ширина бруса ($B_{\text{бруса}}$) в см (по умолчанию 5 см или 8 см)

#### А. Открытый цветник (3 бруса: 2 длинных + 1 поперечный):
> **Официальная формула объёма (см³)**:
> $$\text{Vol}_{\text{см}^3} = (\text{Длина} \times 2 \times \text{Толщина} \times \text{Ширина бруса}) + (\text{Ширина} \times \text{Толщина} \times \text{Ширина бруса})$$

* **Перевод объёма в м³**:
  $$\text{V}_{\text{цветника}} = \frac{\text{Vol}_{\text{см}^3}}{1\,000\,000}$$

#### Б. Сплошная надгробная плита (Закрытый цветник):
* **Объём плиты (м³)**:
  $$\text{V}_{\text{плиты}} = \frac{L_{\text{цв}} \times W_{\text{цв}} \times T_{\text{цв}}}{1\,000\,000}$$

* **Масса цветника (кг)**:
  $$\text{M}_{\text{цветника}} = \text{V}_{\text{цветника}} \times \text{Плотность}$$
* **Цена цветника ($)**:
  $$\text{Cost}_{\text{цветника}} = \text{V}_{\text{цветника}} \times \text{Цена\_за\_м3}$$

---

### 4.5. Расчёт Гравировки и Художественного оформления

1. **Гравировка ФИО и дат**:
   - Ввод текста ФИО, даты рождения и даты смерти (например: *Ступак Александр Иванович 12.05.1950 — 24.11.2023 гг.*).
   - Подсчёт количества знаков (буквы, цифры, символы).
   - Выбор покрытия:
     - **Классическая гравировка**: 1 знак = 0.60 $ (или ~2.00 BYN)
     - **Сусальное золото**: 1 знак = 1.80 $ (или ~5.80 BYN)
   - Формула цены: $\text{Количество\_знаков} \times \text{Тариф\_за\_знак}$.

2. **Эпитафия (надгробная надпись)**:
   - Ввод текста эпитафии (например: *«Помним, любим, скорбим...»*).
   - Подсчёт знаков $\times$ Тариф за 1 знак эпитафии ($0.50 $/знак).

3. **Портрет / Медальон**:
   - Прямая гравировка на граните (стандарт / премиум художником).
   - Фотокерамика / Металлокерамика / Портрет на стекле в нишу.

## 📄 5. Формирование Word-документа (.docx)

При клике на кнопку **«Сформировать документ»** или **«Скачать .docx»** приложение создаёт договор-смету OpenXML (.docx) со следующими обязательными правилами:

### 5.1. Структура документа Docx:
1. **Шапка документа**:
   - Заголовок: `СМЕТА-ДОГОВОР № [Номер Заказа] от [Дата]`
   - Исполнитель: `ИП Ступак О.О.`
   - Адрес: `«ДВА АНГЕЛА» Ольшаны рынок БРОДОК павильон 35`
   - Контакты: `Viber, Telegram тел.: +375295421809, +375297273637`
2. **Блок данных Заказчика и Усопшего**:
   - Заказчик (Ф.И.О., телефон)
   - Ф.И.О. усопшего
   - Адрес установки / Кладбище
   - **Гравировка ФИО (даты рождения/смерти)**: переносится полный текст с сохранением всех дат (например: `12.05.1950 — 24.11.2023 гг.`), спецсимволов и многострочности.
   - **Эпитафия**: переносится полный текст эпитафии из конструктора.
3. **Таблица позиций сметы**:
   - Колонки: `№`, `Наименование работ/материалов`, `Ед. изм.`, `Кол-во`, `Цена ($)`, `Сумма (BYN)`
   - Детализация комплектных памятников, ручных позиций, плитки, оград, доставки и монтажа.
4. **Финансовый итог**:
   - Итоговая сумма в BYN и USD по текущему курсу Нацбанка РБ.
   - Скидка (если применимо).
   - Предоплата (BYN).
   - Остаток к оплате (BYN).
5. **Подписи сторон (без лишниx символов и слэшей)**:
   - `ЗАКАЗЧИК: _____________________ (Ф.И.О.)`
   - `ИСПОЛНИТЕЛЬ: ИП Ступак О.О. _____________________ (М.П.)`

## 💾 6. Структура Реляционной Базы Данных (Database Schema)

Для ПК-версии (SQLite / PostgreSQL / Electron Store / Room / SQLite3) рекомендуется следующая схема таблиц:

### Таблица `orders` (Заказы / Сметы)
- `id` (INTEGER PRIMARY KEY AUTOINCREMENT)
- `order_number` (TEXT, e.g. "№ 2026-084")
- `created_at` (TIMESTAMP)
- `updated_at` (TIMESTAMP)
- `client_name` (TEXT)
- `client_phone` (TEXT)
- `deceased_name` (TEXT)
- `installation_address` (TEXT)
- `status` (TEXT: 'DRAFT', 'ACCEPTED', 'IN_PROGRESS', 'READY', 'COMPLETED')
- `usd_rate` (REAL, e.g. 3.2545)
- `subtotal_usd` (REAL)
- `discount_percent` (REAL)
- `total_byn` (REAL)
- `prepayment_byn` (REAL)
- `remaining_byn` (REAL)
- `notes` (TEXT)

### Таблица `order_items` (Позиции заказа)
- `id` (INTEGER PRIMARY KEY AUTOINCREMENT)
- `order_id` (FOREIGN KEY -> orders.id)
- `category` (TEXT)
- `name` (TEXT)
- `unit` (TEXT)
- `unit_price_usd` (REAL)
- `quantity` (REAL)
- `total_price_usd` (REAL)
- `total_price_byn` (REAL)
- `custom_note` (TEXT)

### Таблица `price_catalog` (Прайс-лист)
- `id` (INTEGER PRIMARY KEY AUTOINCREMENT)
- `category_key` (TEXT)
- `item_name` (TEXT)
- `unit` (TEXT)
- `price_usd` (REAL)
- `description` (TEXT)
- `stone_density_kg_m3` (REAL, optional)
- `suitable_for_engraving` (BOOLEAN)

## ☁️ 8. Облачная База Данных Firebase Firestore и Синхронизация между ПК и Мобильными Устройствами

### 8.1. Принцип Работы Облачной Базы Данных
Приложение поддерживает **гибридную двухуровневую архитектуру (Offline-First)**:
1. **Локальное хранилище**: Все данные первоначально сохраняются локально (Room в Android / SQLite в ПК-версии), гарантируя мгновенную откликаемость UI даже без доступа к интернету.
2. **Облачный движок синхронизации (Firebase Firestore)**:
   - При наличии интернет-подключения и аутентификации пользователя, любые изменения (добавленный заказ, изменённый статус, редактирование прайса) мгновенно передаются через WebSocket/Snapshot Listeners всем подключённым ПК-терминалам и смартфонам.
   - Аутентификация выполняется строго через **Google Sign-In** (Jetpack `CredentialManager` / Firebase Auth).

### 8.2. Структура Коллекций Firestore (Cloud Firestore Schema)

1. **Коллекция `orders` (Сметы и Заказы)**
   - `id`: number (ID заказа)
   - `orderNumber`: string (например, "РК-260826-1100")
   - `clientName`: string (ФИО клиента)
   - `clientPhone`: string (Телефон клиента)
   - `deceasedName`: string (ФИО усопшего)
   - `cemeteryName`: string (Кладбище)
   - `plotNumber`: string (Участок)
   - `createdAt`: number (Timestamp создания)
   - `status`: string ('DRAFT', 'IN_PROGRESS', 'READY', 'PAID', 'CANCELLED')
   - `subtotalAmount`: number (Сумма до скидки)
   - `discountPercent`: number (% скидки)
   - `discountAmount`: number (Сумма скидки)
   - `totalAmount`: number (Итого)
   - `prepaymentAmount`: number (Предоплата)
   - `remainingAmount`: number (Остаток)
   - `itemsJson`: string (JSON-массив составных элементов сметы)

### 8.3. Настройка Конфигурации для ПК и Мобильной Версий
1. Файл `google-services.json` помещается в каталог `app/` для Android-клиентов.
2. ПК-клиент подлючается с использованием `firebaseConfig` (Web SDK или Firebase Admin / C# Firestore Client).
3. Правила доступа Firebase Firestore Security Rules:
```json
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /{document=**} {
      allow read, write: if request.auth != null;
    }
  }
}
```
